# APP-11 SHJJ Brief 모바일 UX 전체 점검

## 0. 목적

SHJJ Brief를 아이폰/갤럭시에서 실제 앱처럼 사용할 수 있도록 모바일 화면의 가독성, 카드 순서, 버튼 배치, 접힘/펼침 흐름을 점검한다.

이번 작업의 목표는 즉시 코드를 수정하는 것이 아니라, preview-main 기준으로 무엇을 먼저 고쳐야 하는지 판단 기준을 정리하는 것이다.

---

## 1. 현재 모바일 UX에서 확인해야 할 핵심 영역

| 영역 | 점검 이유 |
|---|---|
| 오늘날씨 카드 | 첫 화면 핵심 정보 |
| 오늘 행동 가이드 | 날씨 기반 행동 판단 |
| 법령 브리프 카드 | 업무 자동화 핵심 가치 |
| 오늘일정 카드 | 개인/회사 일정 공유 핵심 |
| 알림 시간 설정 | 매일 브리핑 앱으로 쓰기 위한 설정 |
| 초대코드/회사방 참여 UI | 회사 일정 공유 MVP 진입점 |
| 카드 접힘/펼침 | 모바일 화면 길이 관리 |
| 버튼 위치 | 한 손 조작성과 오작동 방지 |

---

## 2. 첫 화면 3초 기준

모바일 첫 화면에서 3초 안에 파악되어야 하는 정보는 다음 4개다.

1. 오늘 날씨가 어떤지
2. 오늘 행동 가이드가 무엇인지
3. 법령/일정에 새로 볼 것이 있는지
4. 내가 다음으로 눌러야 할 영역이 무엇인지

### 판단 기준

| 기준 | 합격 |
|---|---|
| 첫 화면 정보량 | 날씨와 행동 가이드가 바로 보임 |
| 문구 길이 | 한 줄 또는 두 줄 중심 |
| 카드 순서 | 날씨 → 행동 가이드 → 법령/일정 순서 |
| 버튼 | 눌러야 할 버튼이 아래로 밀리지 않음 |
| 시각 피로 | 색상과 그림자가 과하지 않음 |

---

## 3. 오늘날씨 카드 점검 항목

### 확인할 것

- 현재 기온이 가장 먼저 보이는가
- 최고/최저 기온이 한눈에 보이는가
- 강수 확률/바람 등 보조 정보가 과하지 않은가
- 날씨 카드가 행동 가이드보다 위에 있는가
- 아이폰 작은 화면에서 카드 높이가 너무 크지 않은가

### 즉시 수정 후보

- 기온, 상태, 최고/최저 중심으로 요약
- 상세 날씨 정보는 접힘/보조 영역으로 이동
- 카드 내부 여백 과다 여부 확인

---

## 4. 오늘 행동 가이드 점검 항목

### 확인할 것

- 행동 가이드가 너무 긴 문장으로 나오지 않는가
- 사용자가 바로 행동할 수 있는 문장인가
- 날씨와 연결된 이유가 짧게 보이는가
- 상세 설명은 접거나 보조 문구로 빠져 있는가

### 권장 구조

```text
오늘은 얇은 겉옷 추천
아침·저녁 기온차가 있어요
```

### 즉시 수정 후보

- 긴 설명 제거
- 핵심 행동 1개 + 이유 1개 구조 유지
- 과도한 이모지/강조 줄이기

---

## 5. 법령 브리프 카드 점검 항목

### 확인할 것

- 오늘/최근 7일/최근 30일 건수가 헷갈리지 않는가
- 분야별 구분이 모바일에서 잘 읽히는가
- 시행일/공포일/유예일이 한 줄에 들어가는가
- 카드 펼침 시 핵심 변경 요약이 먼저 보이는가
- 원문 링크보다 AI 요약이 먼저 보이는가

### 즉시 수정 후보

- 날짜는 짧은 형식으로 통일 필요
- 긴 법령명은 줄바꿈 기준 정리 필요
- 분야별 접힘/펼침 상태를 기본값으로 정리

---

## 6. 일정 카드 접힘/펼침 점검 항목

### 확인할 것

- 오늘일정 영역이 삭제된 것처럼 보이지 않는가
- 접힘 상태에서도 일정 존재 여부가 보이는가
- 펼쳤을 때 월별 미리보기/일정 목록이 바로 보이는가
- 일정 등록 버튼이 권한에 따라 올바르게 보이는가
- 읽기 권한 사용자는 등록 버튼이 숨겨지는가

### APP-12와 연결되는 항목

일정 카드 UX는 APP-12 사용자 흐름과 직접 연결된다.

- 관리자는 일정 등록/수정 가능
- editor는 일정 등록/수정 가능
- viewer는 일정 확인만 가능
- 퇴사자/비활성화 구성원은 접근 제한

---

## 7. 알림 시간 설정 영역 점검 항목

### 확인할 것

- 알림 시간 입력 UI가 어디에 있는지 바로 보이는가
- 저장 후 피드백 문구가 있는가
- 설정 영역이 첫 화면을 과도하게 차지하지 않는가
- 향후 서버 user_settings와 연결 가능한 구조인가

### 판단

현재는 localStorage 저장이어도 되지만, APP-14 이후에는 서버 user_settings와 연결하는 것이 맞다.

---

## 8. 초대코드/회사방 참여 UI 점검 항목

### 확인할 것

- 초대코드 입력창과 PIN 입력창이 명확히 구분되는가
- 복사 버튼이 코드 아래로 밀리지 않는가
- 긴 초대코드가 모바일 폭을 깨지 않는가
- 참여 성공/실패 메시지가 명확한가
- 권한이 없는 사용자가 일정 등록을 시도할 수 없는가

### 즉시 수정 후보

- 초대코드는 짧은 고정 길이 사용
- 복사 버튼은 같은 줄 또는 별도 작은 버튼으로 정리
- 실패 메시지는 짧고 명확하게 표시

## 9. 버튼 밀림/잘림/가독성 점검 기준

| 항목 | 합격 기준 |

| 버튼 높이 | 손가락으로 누르기 충분한 크기 |
| 버튼 폭 | 텍스트가 줄바꿈으로 깨지지 않음 |

## 15. APP-12 일정 공유 흐름과 연결

APP-11은 화면 사용성 점검이고, APP-12는 실제 사용자 흐름 정리다.

따라서 APP-11에서 확인한 UX 문제는 APP-12에서 다음 흐름으로 연결되어야 한다.

```text
관리자 회사방 생성
→ 직원 초대코드 발급
→ 직원 참여
→ 권한별 일정 확인/등록
→ 퇴사자 비활성화
```

특히 초대코드 입력, 권한 표시, 일정 등록 버튼 노출 여부는 APP-12에서 상세 흐름으로 확정해야 한다.

## 16. 최종 UX 판단 기준

SHJJ Brief 모바일 UX의 최종 기준은 다음이다.

```text
앱을 열었을 때 3초 안에 오늘 필요한 정보를 보고,
추가 행동이 필요하면 헷갈리지 않고 다음 버튼을 누를 수 있어야 한다.
```

### 최종 합격 기준

- 첫 화면에서 날씨와 행동 가이드가 바로 보인다.
- 법령/일정의 새 정보 여부가 바로 보인다.
- 회사방 참여와 일정 공유 흐름이 막히지 않는다.
- 버튼이 밀리거나 잘리지 않는다.
- 한글 깨짐이 없다.
- main이 아니라 preview-main에서 먼저 검수된다.
